エンジニアチームボード（https://trello.com/b/Cl0LXg3W/エンジニアチーム）を Trello MCP で読み、
今日のタスクプランを組み立てて提示する。退勤目標: $ARGUMENTS（未指定なら 17:00）。

## 手順

1. `trelloReadCard`（list_by_board）でエンジニアボードの全カードを取得する（リスト・ラベル・期限つき）
2. 現在時刻から退勤目標までの実働時間を見積もる（昼休憩と割り込みバッファを差し引く）
3. **弁護士案件は重めに見積もる**（カード名に「◯◯先生」を含む、または弁護士への確認・
   ヒアリングが要るもの）。目安は通常の1.5倍。会議や期日で捕まらず DM 往復の待ちが出るため、
   連絡の初手はなるべく早い時間帯に置き、返信待ちの間に別ブロックを進める組み立てにする

## 分析の優先順位（この順で地雷を検出する）

1. **業務停止**: 名前に【業務停止】を含むカード。担当未設定の業務停止は最悪なので最初に指摘
2. **今日期限**: 期限が今日のカード。やるか、今日中に期限交渉するか
3. **明日期限**: 明日が期限のカード。無理な分は「今日のうちに」交渉コメント（前日の交渉は誠実、当日は事故）
4. **WIP純度**: 「作業中」が1人2枚を超えていたら、今日触らない分を「対応予定」へ下げるよう指摘
5. **チーム内待ち**: 「待ち:山田」「待ち:藤川」ラベルのカード（相手の確認を止めているのは自分かもしれない）
6. **同種カードの束ね**: 同じシステム・同じスプレッドシートに関するカードは1ブロックにまとめて処理を提案

## 出力

- 冒頭に「17時退勤を脅かす地雷」を最大3つ
- 時間帯別のタイムテーブル（Markdownテーブル）。集中ブロック（90分単位）＋バッファ＋16:30からの締め（完了カードの終了処理・明日の対応予定の並び替え）を含める
- 藤川さんへの申し送りがあれば1〜2行で
- 最後に、計画に沿ったカード移動（作業中→対応予定への降格や並び替え）を MCP で代行するか確認する
- ただし非対話（`claude -p`、run.py からの自動実行）で走っている場合は、確認できないので
  カード移動の提案は日報に書くだけにする（Trello の書き込みツールは許可されていない）

## 日報への書き込み（その日の初回のみ）

プランを提示したら、同じ内容を今日の日報にも書き込む（チャットに出して終わりにしない）。
ただし書き込むのは **plan ブロックにまだ中身が無いときだけ**。

- 日報: `~/workspace_tyamada/daily-startup/data/notes/daily/YYYY/YYYY-MM-DD.md`（今日の日付）
- 無ければ先に `cd ~/workspace_tyamada/daily-startup && python3 daily.py` で作る（冪等）
- 書き込むのは `<!-- plan:begin -->` 〜 `<!-- plan:end -->` の間
- **`<!-- plan:begin -->` 〜 `<!-- plan:end -->` に既に中身があれば日報には書き込まない**（チャット提示のみ）。
  日報の plan ブロックは「今日の意図の記録」なので、午後の再計画で上書きしない。
  朝のプランを書き直したいときは、ユーザーがブロックの中身を空にしてから実行する（それが上書きの意思表示）
- ブロック自体がまだ無ければ `<!-- auto:begin` の行の**直前**に挿入する（auto ブロックは daily.py が毎回丸ごと書き換えるので、その中には絶対に書かない）。auto ブロックも無ければファイル末尾に足す
- 内容: 見出し `## 今日のプラン（HH:MM時点・退勤目標 HH:MM）` → 地雷 → タイムテーブル → 申し送り

## 原則（このプロジェクトの流儀）

- 期限は外部との約束のみ。内部計画は並び順で表現する
- 作業中＝今日実際に手が動くものだけ
- 判断に迷うものは提案に落とし、勝手にカードを動かさない
