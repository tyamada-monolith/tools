# daily-startup

朝の日報ファイル作成と、Trello「エンジニアチームタスク」の取り込み。

## 叩き方

```sh
python daily.py          # 日次データだけ作る（平日のみ・UI 無し・何度叩いても同じ）
python daily.py --force  # 土日でも作る
python run.py            # daily.py + VSCode と Chrome を開く（従来の入口）
```

**2つに分けてある理由**：Dropbox → Google Drive の移行作業などで PC をつけっぱなしにすると、
朝に `run.py` を叩かない日ができる。`run.py` にデータ生成が混ざっていると、その日のデータが
まるごと欠ける。`daily.py` は UI を触らないので、時刻トリガーからでも叩ける。

## 叩き忘れた日

`daily.py` は、最後に存在する日報の翌日から昨日までで**抜けている平日の日報ファイルを作る**
（上限14日。祝日は判定していない）。

ただし **Trello スナップショットは遡れない**。Trello に「3日前の盤面」を返す API はないため、
欠損日は日報の枠だけができる。差分は「昨日」固定ではなく**直近に存在するスナップショット**と
比較するので、空いた期間をまたいで `2026-07-30 → 2026-08-04（3営業日ぶり）` として繋がる。

完全に手を離したい場合は、Windows タスクスケジューラから平日に叩く。
WSL の cron は WSL インスタンスが起きていないと動かないので、つけっぱなしでも当てにならない。

```
wsl.exe -d <ディストロ名> -- bash -lc 'cd ~/workspace_tyamada/daily-startup && python3 daily.py'
```

環境変数は要らない（「セットアップ」参照）。`bash -lc` は `~/.zshrc` を読まないので、
シェル設定に依存する作りにしてはいけない。

## 日報ファイルの書き分け

`data/notes/daily/YYYY/YYYY-MM-DD.md` の末尾に自動生成ブロックがある。

```markdown
（ここは人が書く。機械は絶対に触らない）

<!-- auto:begin ここから下は daily.py が毎回書き換えます。手書きは上に -->
## TODO（手書き: todo.txt）
## Trello: エンジニアチームタスク
<!-- auto:end -->
```

ブロックは**追記ではなく置換**なので、何度叩いても二重にならない。
**ブロックの中に手書きしないこと**（次の実行で消える）。

Trello の取得に失敗したときは、その日すでに書けている一覧を残す（空の内容で上書きしない）。

## Trello 一覧の形

1カード1行。`grep` と `diff` が効くように区切りを固定している。

```
- [ ] 🟡 08/14 17:00 | インターン生スプレッドシート改定 | 片桐杏理,竹田航 | 停滞3d | https://trello.com/c/3OfjIjuM
- [ ] ⚪ 期限なし | 髙月先生PC交換対応 | 藤川詩乃 | 停滞15d | https://trello.com/c/WzZLOWzy
```

**並びは Trello のリスト順（`pos`）＝優先度。** Trello に優先度フィールドは無いので、
リスト上でカードを上下に動かした順をそのまま優先度として扱う。日報側で並べ替えはしない。

マークは期限の状態。優先度順に並べても期限が読めるようにしてある。

| | |
|---|---|
| 🔴 | 期限切れ |
| 🟠 | 期限まで2日以内 |
| 🟡 | 期限あり |
| ⚪ | 期限なし |
| ✅ | 期限クリア済（dueComplete） |

🔴 と 🟠 は優先度順だと下に埋もれるので、前回比の下に一覧で拾い直している。

`停滞Nd` は最終更新からの日数。`stale_days`（既定14）を超えたものは前回比に一覧で出る。
メンバー名はソートして固定している（Trello の返す順は不定なので、放置すると差分がブレる）。

## 溜まるもの

```
data/                                  # .gitignore 済み（丸ごと）
├── todo.txt                           # 手書き。Trello へ寄せていく方針なので最終的に空になる
├── notes/daily/2026/2026-08-04.md     # 日報 = 日次の蓄積そのもの
└── trello/engineer-team/
    └── 2026/2026-08-04.json           # 差分計算の正
```

md ではなく **json を差分の正にしている**。md で diff を取ると表記ゆれでノイズが出る。
1日あたり数十 KB なので、間引きは考えていない。

## セットアップ

設定は要らない。認証情報は下記の順に探し、見つかったものを使う。

1. 環境変数 `TRELLO_API_KEY` / `TRELLO_TOKEN`
2. `TRELLO_ENV_FILE` が指すファイル（指定時はこれだけを見る）
3. `daily-startup/.env`
4. `monolith-gas/trello-tools/trello-card-automator/.env` ← **通常はこれで動く**

4 のパスを `src/trello.py` に直接書いてある。トークンを2か所に複製したくないため。
**シェルの設定に依存させないこと**が理由でもある。スケジューラは `bash -lc` で叩くので
`~/.zshrc` は読まれず、そこに `export` を書いても自動実行だけ失敗する。

トークンを分けたい場合は `.env.example` をコピーして `daily-startup/.env` を作る（3 が優先される）。
`monolith-gas` を移動・改名したら「認証情報がありません（探した先: ...）」で止まるので、
黙って空データになることはない。

`.env` は `.gitignore` 済み。エラーメッセージに載らないよう、API キーとトークンは
`src/trello.py` の `scrub()` を通してから出している（Trello はクエリ文字列で認証するため、
URL をそのまま出すとトークンが平文で残る）。

## 取得対象を変えるとき

`src/snapshot.py` の `CONFIG` の `list_id` を差し替える（1リストしか見ないので設定ファイルは持たない）。
`slug` は `data/trello/` 配下のディレクトリ名になるので、変えると蓄積が別系列になり
過去分との差分が切れる。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `daily.py` | 日次データの入口。欠損日補完 → 日報生成 → Trello 取得 → ブロック書き込み |
| `run.py` | `daily.py` + VSCode / Chrome |
| `src/note.py` | 日報ファイルの生成・自動生成ブロックの置換 |
| `src/trello.py` | Trello REST。取得のみ |
| `src/snapshot.py` | json の蓄積・前回比の算出・Trello セクションの整形 |
| `src/urls.py` | Chrome の URL グループを開く |
